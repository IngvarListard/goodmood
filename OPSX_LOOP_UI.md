# OPSX_LOOP_UI — генерация дизайна UI

Методология генерации дизайна для трекера настроения. Не «придумать визуальный язык с нуля», а «компоновать DaisyUI под сценарии из спек».

## Когда генерировать

```
Сейчас:    дизайн-эксплор для решения OQ1 (состав минимальной формы, Фаза 0)
Позже:     финальный дизайн по фазам, в имплементационных change'ах
           Фаза N → design.md change'а содержит экраны/флоу
```

Дизайн-эксплор — инструмент, чтобы закрыть open questions из `product-vision/design.md`. Увидев мокап, проще решить состав полей, оси розы ветров, формат вечерних инсайтов и т.д.

## Две дорожки инструментов

| | Дорожка A (визуальный референс) | Дорожка B (прямо в стек) ⭐ |
|---|---|---|
| Инструменты | v0.dev, Lovable, Figma AI First Draft | Claude / GPT / Cursor с hiccup-preview |
| Вывод | React/Tailwind или Figma | hiccup2 + DaisyUI + htmx |
| Когда | нужен «чувственный» exploration, layout-идеи | реализация конкретного экрана |
| Минус | не наш стек, перенос вручную | слабее в визуальной новизне |

**Рекомендация:** Дорожка B основная (прямой путь в код), Дорожка A — когда зайдёшь в тупик с layout'ом.

## Промпт-шаблон (вставлять в каждый запрос)

```
[КОНТЕКСТ]
Продукт: трекер настроения для людей со спектральной аффективной
нестабильностью. Состояние описывается многомерной «розой ветров»
(энергия/тревога/фокус/...), не одной цифрой. Ядро ценности — возврат
пользователю его же инсайтов в нужный момент.

[СТЕК]
Clojure, hiccup2 (html/raw), Tailwind + DaisyUI, htmx, hyperscript.
Mobile-first. PWA. Вывод — hiccup2 вектор, не HTML-строка.

[ЭКРАН]
<из spec сценария> — например: «минимальная форма создания записи,
шаблон "утро", опциональные блоки»

[КОНТЕНТ]
- поля: <список>
- состояния: <например: пусто / заполнено / ошибка / мягкий режим>

[ТОН И UX-约束 — ОБЯЗАТЕЛЬНО]
- спокойная палитра, не стимулирующая; тёмная тема как дефолт
  (фотосенситивность, депрессия)
- крупные touch-targets (≥44px), читаемость при «голова не соображает»
- прощающие ошибки: мягкие алерты, не красные, не «ошибка!»
- поддерживающий copy, без вины («цепочка разорвана» и т.п. запрещено)
- минимум когнитивной нагрузки, максимум опциональности
- мягкий режим в плохом состоянии: акцент на совете, не на фиксации боли

[ОГРАНИЧЕНИЯ]
- никаких стриков/геймификации давления
- никаких «вы пропустили день»
- опциональные блоки явно выделены как skip-able
- не использовать emoji без явного запроса

[ФОРМАТ]
Верни hiccup2-вектор одного экрана. Без ns, без (:require). Только тело.
```

## Доменные UX-约束 (повторять в каждом промпте)

Критично — обычные AI склонны к «весёлому» дизайну, который травмирует целевую аудиторию:

- **Тёмная тема как дефолт** — фотосенситивность + депрессия
- **Спокойная палитра** — не стимулировать, не давить
- **Минимум когнитивной нагрузки** — пользователь в плохом состоянии не должен «декодировать» интерфейс
- **Прощающие ошибки** — мягкие алерты, не красные
- **Поддерживающий copy** — никакого гильт-языка
- **Крупные touch-targets** — мобайл + состояние «руки не слушаются»
- **Soft mode** — в плохом состоянии акцент на совете, не на фиксации боли

## Луп генерации

```
1. Возьми сценарий из spec (Фаза 0: «минимальная форма», spec.md)
2. Сформируй промпт по шаблону выше
3. Сгенерируй hiccup2 → вставь в dev/preview.clj (в (def body …))
4. Запусти clj -M -i dev/preview.clj → открой resources/proto/preview.html
   (скрипт оборачивает hiccup в полный HTML с DaisyUI/Tailwind/htmx/hyperscript
   через CDN, тёмная тема по дефолту)
5. Если не нравится — корректируй промпт, не код
6. Зафиксируй финальный вариант:
   — в имплементационном change design.md (визуальное описание + код-референс)
   — или сразу в src/app/views/*.clj
7. Прогон через кодстайл/CODESTYLE.md
```

### dev/preview.clj

Скрипт-предпросмотрщик уже лежит в `dev/preview.clj`:
- `body` — место для hiccup-вектора (помечено PLACEHOLDER)
- обёртка: `<html data-theme="dark">`, Tailwind + DaisyUI CDN, htmx, hyperscript
- вывод: `resources/proto/preview.html` (открывается `file://` в браузере)
- запуск: `clj -M -i dev/preview.clj`

## Пример: стартовый промпт для Фазы 0

```
[ЭКРАН]
Минимальная форма создания записи состояния, шаблон "утро".
Открывается по «+» из ленты. После сохранения — закрытие и возврат в ленту.

[КОНТЕНТ]
- ядро: 3 ползунка-оси розы ветров (энергия 0-10, тревога 0-10, фокус 0-10)
- опционально: сон (часы), свободная заметка, настроение 0-10
- кнопка «сохранить»
- состояние: пусто / заполнено частично / сохраняется (htmx-swap)

[ДОПОЛНИТЕЛЬНО]
- показать, как ползунки формируют мини-розу ветров в реальном времени
- (hyperscript: on input пересчитывать визуал)
```

| Решение open question | `product-vision/design.md` (убрать из Open Questions, зафиксировать решение) |
