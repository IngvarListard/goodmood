# Инструкция оркестратору: редизайн по дизайн-референсам

Ты — оркестратор. Твоя задача — провести 4 изменения OpenSpec от начала до конца,
работая автономно. Основную сессию не засорять: реализацию выполнять через сабагентов.

## Порядок изменений (строгий)

1. `redesign-tokens` — фундамент (палитра, Inter, gm-* классы, bottom nav)
2. `redesign-feed`
3. `redesign-check-in`
4. `redesign-insight-form`

2–4 зависят от 1. Между собой независимы, но выполняются ПОСЛЕДОВАТЕЛЬНО:
все трое правят `resources/i18n/{ru,en}.edn` — параллельные правки конфликтуют.

## Контекст (прочитать до старта, один раз)

- `AGENTS.md` — стек, конвенции, htmx-философия (никакого сырого JS), i18n, e2e
- `CODESTYLE.md`, `CLOJURE-RULES.md` — стиль кода
- `design/lenta.html`, `design/otmetka.html`, `design/new-insight.html` — референсы
- Артефакты каждого change: `openspec/changes/<name>/{proposal,design,specs,tasks}.md`

## Цикл на каждое изменение

1. Прочитать артефакты change (proposal → design → specs → tasks).
2. Каждую задачу tasks.md выполнять через task-сабагента (subagent_type: `general`).
3. После задач: верификация оркестратором лично (см. ниже), затем `openspec archive`.

### Правила делегирования сабагентам

- Промпт сабагента — САМОДОСТАТОЧНЫЙ: он не видит твою сессию. Передавай:
  - задачу из tasks.md целиком (текст задачи, файлы, референс-строки макета)
  - критерии приёмки и команду проверки из задачи
  - указание прочитать AGENTS.md, CODESTYLE.md, CLOJURE-RULES.md
  - правило: hyperscript/hx-атрибуты/имена полей не менять (если задача не об этом)
- Один сабагент = одна задача tasks.md. Не собирать несколько задач в один промпт.
- Сабагент возвращает: список изменённых файлов + что проверил + отклонения от задачи.
- Если сабагент эскалировал (см. ниже) — разобрать эскалацию в основной сессии.

### Верификация оркестратором (лично, не делегировать)

- Playwright MCP: открыть затронутые страницы, кликнуть, проверить htmx-свапы,
  обе локали (cookie gm-locale=ru / gm-locale=en), тёмную тему (gm-theme=dark)
- e2e: `cd e2e && npx playwright test` (webServer переиспользует запущенный app;
  e2e-юзер: `clojure -M -i dev/seed_e2e_user.clj`, логин e2e@goodmood.test /
  e2e-test-password-123)
- Приложение запущено? `curl http://localhost:3000/` ; если нет — `clj -M -m app.core`
- Только после зелёной верификации: git commit (по коммиту на change,
  сообщение в стиле репозитория), затем `openspec archive <name>`

## Эскалация к человеку — ТОЛЬКО если

- противоречие между дизайн-референсом и существующей функциональностью
  (например, макет требует убрать поле, которое нужно по спеке)
- e2e падает и не чинится за 2 итерации
- нужна новая зависимость или миграция БД
- сломан существующий htmx-контракт, который задача требовала сохранить дословно

Во всех остальных случаях решать самостоятельно и продолжать. Не задавать вопросов,
если ответ выводим из артефактов change (design.md содержит решения и trade-offs).

## Запрещено

- Сырой JavaScript (только htmx-атрибуты и hyperscript)
- Скриншоты/пиксельная сверка (дизайн не устоялся)
- Правки light-темы (`[data-theme=light]` в layout.clj не трогать)
- Коммиты секретов; правки вне разрешённых задачей файлов без причины (причина — в отчёте)

## Известные решения, принятые человеком (не пересматривать)

- Light-тема остаётся прежней (вариант B): dark перекрашивается, light не трогаем
- up-arrow кнопки в textarea макета new-insight — артефакт, не включать
- Ширина контента страниц — `max-w-md mx-auto`; десктоп-сайдбар остаётся
- Timeline в ленте — новый компонент, старые компактные карточки заменяются
