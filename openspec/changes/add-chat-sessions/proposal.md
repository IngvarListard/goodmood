# Proposal: add-chat-sessions

## Why

Чат ассистента живёт в одной вечной ленте `ai_chat_messages` без разделения на разговоры: модель получает только **последние 8 сообщений** — через десять сообщений ассистент «забывает» начало разговора; старые сообщения навсегда смешиваются с новыми. Привычное поведение («сессия чата» — отдельный разговор, «новый чат» начинает чистый) отсутствует. Попутно: сессия логина умирает через час (`max-age 3600`) — пользователь перелогинивается по нескольку раз в день; владелец хочет 3 месяца.

## What Changes

- Миграция: `ai_chat_messages.session_id` — сообщения группируются в сессии-разговоры
- Текущая сессия юзера = сессия с максимальным `session_id` (указатели не хранятся)
- **Полный контекст**: модель получает ВСЕ сообщения текущей сессии (не последние 8); UI истории тоже показывает всю сессию
- Кнопка «новый чат» в шапке ассистента: `POST /ai/chat/new` создаёт новую сессию, свапает панель на пустую; старая сессия остаётся в БД
- Сессия логина: `max-age` куки `gm-session` — 90 дней вместо 1 часа (не скользящая)
- Non-goal (будущий change): compact длинной истории перед отправкой модели — владелец явно отложил

## Capabilities

### New Capabilities

- Нет отдельной новой capability; поведение чата расширяет `ai-assistant`

### Modified Capabilities

- `ai-assistant`: сессии чата и полный контекст сессии для модели
- `assistant-modal`: история модалки = текущая сессия; кнопка «новый чат»
- `users-auth`: срок жизни сессии 90 дней (браузерная enforcement через Max-Age)

## Impact

- Миграция `resources/migrations/002-chat-sessions.{up,down}.sql` (append-only): `ALTER TABLE ai_chat_messages ADD COLUMN session_id INTEGER NOT NULL DEFAULT 1` — существующая лента становится сессией №1
- `app.db.ai` / `app.domains.ai`: запросы по session_id, `current-session-id`, `new-session!`, контекст = все сообщения сессии
- `app.routes.ai` / `app.views.ai`: кнопка «новый чат», роут
- `routes/app.clj`: одна константа `:max-age`
- i18n: «Новый чат»
- Риск: низкий; миграция с down.sql, деплой ловит health-check'ом

## Scope

Сессии чата (полный контекст + новый чат) и срок жизни сессии логина.

## Non-goals

- Compact истории (будущий change, явно отложен владельцем)
- UI-история прошлых сессий («список разговоров»)
- Скользящее продление сессии логина (re-issue при активности)
- Серверная инвалидация сессии по timestamp — см. design: существующая спека описывала нереализованное поведение, дельта фиксирует фактическую модель
