## Why

Пользователю нужен визуальный способ добавлять и просматривать записи дневника
без работы с API напрямую — это первый видимый конечному пользователю кусок
продукта.

## What Changes

- Добавлен hiccup2-шаблон формы добавления записи (`activity`, `effect`,
  `mood_score`, `sleep_hours`)
- Добавлен hiccup2-шаблон списка записей
- Добавлены htmx-атрибуты (`hx-post`, `hx-target`, `hx-swap`) для добавления
  записи без перезагрузки страницы
- Добавлена базовая стилизация формы и списка через Tailwind + DaisyUI
- Роут `POST /entries` (из change `add-entries-api`) теперь возвращает HTML-фрагмент
  нового элемента списка вместо JSON, если запрос пришёл от htmx (проверка
  заголовка `HX-Request`)
- Для валидных htmx-запросов ответ по-прежнему успешный (200/201), фрагмент списка
  обновляется на странице; для невалидных — возвращается HTML-фрагмент с сообщением
  об ошибке
- **BREAKING**: `POST /entries` меняет формат ответа для htmx-запросов (заголовок
  `HX-Request`). Для чистых API-клиентов (без заголовка) формат остаётся JSON.

## Capabilities

### New Capabilities
- `entries-ui`: HTML-страница со списком записей дневника и формой добавления,
  обмен HTML-фрагментами через htmx без перезагрузки страницы, базовая
  стилизация через Tailwind + DaisyUI

### Modified Capabilities
- `entries-api`: `POST /entries` для htmx-запросов (заголовок `HX-Request`)
  возвращает HTML-фрагмент вместо JSON; `GET /entries` для браузерных запросов
  возвращает HTML-страницу вместо JSON-массива

## Impact

- Затрагивает: `app.domains.entries.views` (новый namespace, hiccup2-шаблоны),
  `app.domains.entries.handlers` (формат ответа `POST /entries` для htmx),
  `app.routes` (рендеринг страницы для `GET /entries`, раздача статики:
  htmx-скрипт, Tailwind/DaisyUI CSS)
- Новые ресурсы: статические файлы для htmx и Tailwind/DaisyUI (CDN или локально)
- Зависит от: `add-entries-api` (роуты и валидация уже реализованы)
- Пользователи: первая видимая конечному пользователю функциональность приложения

## Scope

- **In scope**: страница со списком + формой, htmx-добавление записи без reload,
  обработка ошибок валидации в виде HTML-фрагмента, базовые стили
- **Out of scope / Non-goals**: статистика, психотерапевтический дневник,
  клиентская валидация формы, редактирование/удаление записей, пагинация

## Acceptance Criteria

- GIVEN пользователь открывает GET /entries в браузере
  WHEN страница загружается
  THEN отображается форма добавления записи и список существующих записей
- GIVEN пользователь заполняет форму и отправляет её
  WHEN htmx отправляет POST /entries
  THEN новая запись появляется в списке без перезагрузки страницы
- GIVEN mood_score вне диапазона 0-10 введён в форму
  WHEN форма отправлена
  THEN сервер возвращает HTML-фрагмент с сообщением об ошибке вместо добавления записи

## Non-functional requirements

- Страница должна оставаться читаемой и функциональной на мобильном экране
  (viewport 375px)
- htmx-запросы должны сохранять поведение JSON-API `POST /entries` для чистых
  API-клиентов (без заголовка `HX-Request` — прежний JSON-ответ)
