## Context

Навигация из change `navigation-skeleton` (архив от 2026-08-11): два nav в DOM, скрываются CSS
media query, пункты — `<button type="button">` без обработчиков, активность — параметр `:active`
(на реальной странице не передаётся). Стек: Tailwind v4 browser CDN + DaisyUI 5.7.15 (CDN),
htmx 2.0.10, hyperscript, hiccup2, reitit.

Найденные дефекты:
1. Иконки сайдбара скачут по горизонтали: кнопки inline-block шириной в контент, иконка
   центрируется внутри своей кнопки → ось зависит от длины лейбла. Плюс `span.w-6.h-6` —
   inline-элемент, size-утилиты не применяются; svg heroicons без width/height атрибутов.
2. Мобильный бар не фиксируется к низу viewport, хотя разметка `fixed bottom-0 inset-x-0`
   корректна (опросом пользователя подтверждено поведение, а не классы) → требует верификации
   computed style в браузере.
3. Нажатия ничего не делают; активный пункт не виден на реальной странице.

## Goals / Non-Goals

**Goals:**
- Единая модель выбора раздела: серверная, от пути роута, с реальной навигацией.
- Выравнивание иконок по единой оси в обеих ориентациях панели (исправление контейнеров).
- Мобильный бар закреплён к низу viewport поверх контента, с учётом safe-area.
- Конвенции даisyUI: `menu`-компоненты, hover/active-анимации из коробки.
- Весь UX-код без новых зависимостей (htmx/hyperscript уже в layout).

**Non-Goals:**
- Реальные экраны разделов — только заглушки.
- Клиентский toggle активности (hyperscript) — активность серверная.
- Btm-nav компонент: **daisyUI 5.7.15 удалил `btm-nav`** (проверено по CDN-файлу) — бар остаётся
  кастомным на `menu menu-horizontal` в фиксированной обёртке.

## Decisions

**1. Сайдбар — daisyUI `menu menu-vertical` (решение пользователя: «по конвенции daisyUI»).**
`ul.menu > li > a`: пункты `w-full`, иконка рядом с лейблом в фиксированном боксе. Активный —
solid-иконка + `menu-active`-стили + `aria-current="page"`. Hover/focus/transition — встроены.
Альтернативы: кастомные кнопки с фиксами (w-full + иконка-бокс) — отклонено, дублирует то, что
menu даёт конвенционально.

**2. Мобильный бар — `menu menu-horizontal` в фиксированной обёртке.**
Обёртка: `md:hidden fixed bottom-0 inset-x-0 z-50 bg-base-100 border-t border-base-200
pb-[env(safe-area-inset-bottom)]`; пункты через `flex-1` растягиваются на равную ширину
(иконки на общей оси). `btm-nav` в daisyUI 5 нет — кастомный бар сохраняется.

**3. Навигация — `<a href>` + `hx-boost` на body.**
hx-boost перехватывает клики по ссылкам, GET страницы, swap body без релоада; без JS —
обычный переход. Активный пункт вычисляется сервером из пути. Альтернативы: кнопки с
hyperscript-toggle — отклонено пользователем (серверная модель); обычные ссылки без htmx —
отклонено, теряем SPA-переходы в инфраструктуре, которая уже есть.

**4. `:active` — серверный, от пути роута.**
Каждая страница передаёт layout `{:active (keyword (subs (request path) 1))}` (для /entries
и прочих не-навигационных путей — nil → ничего не подсвечено). Заглушки вычисляют через общий
хелпер в views/placeholder.clj.

**5. `app.icons/svg` — иконка в настоящем боксе, svg с явным размером.**
Обёртка: `inline-flex items-center justify-center w-6 h-6 shrink-0` (вместо inline-span,
где size не применялся). В загруженную svg-строку инжектятся `width="24" height="24"` при
загрузке (memoize, один раз) — детерминированный размер, без CSS-костылей.
Альтернативы: CSS-правило `span>svg{width:100%}` — отклонено (доп. CSS вне иконки);
классы на самом svg — hiccup2 raw не позволяет атрибуты на вставленном узле.

**6. htmx-атрибуты — в мапе параметров** (конвенция проекта): `[:body {:hx-boost "true" ...}]`.

## Risks / Trade-offs

- [Мобильный `fixed` не применяется в браузере, хотя классы верны] → на этапе реализации
  верифицировать computed style `position: fixed` мобильного nav в devtools; если утилита не
  генерируется (Tailwind browser CDN) — явный `<style type="text/tailwindcss">`-блок для `.fixed`.
- [Tailwind browser CDN и hx-boost-подменённый body] → CDN сканирует DOM по MutationObserver,
  новые классы подхватываются; проверить вручную после первого AJAX-перехода.
- [hx-boost + существующие htmx-формы POST] → hx-boost обрабатывает только `<a>`, формы
  entries затронуты не будут; проверить тестами/в браузере.
- [Два menu в DOM (desktop+mobile)] → скрытие CSS-медиа-запросами, как было у skeleton —
  двойной вес незначителен.
- [safe-area env() не поддержан] → просто нет нижнего отступа, панель работает — приемлемо.
- [Заглушки станут «настоящими» страницами] → активность уже серверная и рельсо-зависимая,
  замена заглушки не потребует переделки навигации.
