## Context

Проект `goodmood` — трекер настроения для людей со спектральной аффективной нестабильностью. Текущая форма (`activity`, `effect`, `mood_score`, `sleep_hours`) не mobile-first, содержит 3 обязательных текстовых поля, требует вдумчивого ввода. Основатель её не заполняет. Продукт-вижн (`product-vision`, Фаза 0) ставит MVP-форму как блокер: без неё продукт не запускается.

Решение OQ1 (2026-08-18) зафиксировало:
- Ядро: mood_score (0–10), energy (0–10), anxiety (0–10) — range-слайдеры
- Опциональные блоки: focus (0–10), sleep_hours, note, activity
- Шаблоны: утро (ядро + sleep_hours), день (ядро), вечер (ядро + sleep_hours + note), событие (ядро + activity + note)
- Целевое время: ядро ≤ 5 сек (3 движения пальца)

Технологии: Clojure, hiccup2 (html/raw), Tailwind + DaisyUI, htmx, hyperscript, SQLite, HoneySQL, next.jdbc, migratus.

## Goals / Non-Goals

**Goals:**
- Перевести форму на mobile-first с range-слайдерами, template-табами и collapse-блоками
- Реализовать мягкий режим (шаблон «день» — только ядро)
- Включить тёмную тему как дефолт
- Миграция БД: новые колонки, снятие NOT NULL с устаревших полей
- Обновить API и UI так, чтобы форма не требовала полной перезагрузки страницы (htmx-swap)

**Non-Goals:**
- Роза ветров состояний — Фаза 2
- AI-ассистент, инсайты, медикаменты — Фазы 1–7
- PWA manifest, service worker — отдельный change
- Регистрация новых пользователей — out of scope
- Стрики, геймификация — запрещены
- Нативные мобильные клиенты — mobile-first означает адаптивный веб

## Decisions

### 1. Range-слайдеры вместо текстовых полей для числовых шкал

Шкалы настроения/энергии/тревоги/фокуса реализуются как `<input type="range">` 0–10 вместо `<input type="number">`. Выбранный `<input type="range">`, а не emoji-селектор, потому что:
- Не используем emoji (требование продукта)
- Range даёт непрерывную шкалу, визуально быстрее чем ввод цифр
- DaisyUI `range` с цветовыми вариантами (primary/success/warning/info) различает оси без чтения

Альтернатива рассмотрена: emoji-селектор 1–5. Отклонена из-за запрета emoji в требованиях.

`[ref: A3-q1, A2-q1]`

### 2. DaisyUI collapse для опциональных блоков

Опциональные блоки реализуются как `<div class="collapse collapse-arrow">` с checkbox-переключением. Это чисто CSS-решение (DaisyUI), не требующее JavaScript.

Почему collapse, а не условный рендеринг:
- Пользователь сам решает, что раскрыть — collapse сохраняет все поля в DOM
- Значения уже раскрытых блоков не теряются при переключении шаблона (в отличие от условного рендера)
- Меньше логики на клиенте — проще реализация Фазы 0

### 3. Tabs для переключателя шаблонов

Шаблоны реализуются как DaisyUI `tabs-boxed`. При клике на таб — визуальное переключение активного таба (Hyperscript: `remove .tab-active from .tab then add .tab-active to me`).

В Фазе 0 табы не управляют видимостью опциональных блоков динамически — все блоки всегда доступны как collapses. Табы служат визуальной подсказкой и сохраняют выбранный шаблон в скрытое поле `template` для аналитики.

Почему не динамическое скрытие:
- Упрощает первую итерацию
- Пользователь не теряет уже введённые данные в скрытых блоках
- Динамическая фильтрация блоков может быть добавлена в будущем без изменения модели данных

### 4. Тёмная тема как дефолт

`data-theme="dark"` в `<body>` layout.clj. Обоснование:
- Фотосенситивность у части пользователей (депрессия, мигрени)
- Меньше визуального шума при когнитивной нагрузке
- DaisyUI dark theme не требует дополнительных CSS-переменных

### 5. Мягкий режим через шаблон «день»

Шаблон «день» содержит только ядро (mood_score, energy, anxiety). Ни один опциональный collapse не развёрнут. Это минимальный viable ввод для пользователя в плохом состоянии — три движения пальца, 5 секунд.

`[ref: A2-q3]`

### 6. Мягкая валидация: alert-warning вместо alert-error

Ошибки валидации отображаются в `alert alert-warning` (жёлтый/янтарный), а не `alert-error` (красный). Обоснование:
- Красный цвет тревожит пользователя в уязвимом состоянии
- «Прощающие ошибки» — тон требования
- Инлайн-ошибка появляется мягко, не прерывает поток

### 7. Миграция 004

Добавляет колонки `energy`, `anxiety`, `focus`, `note` через ALTER TABLE. SQLite не поддерживает ALTER COLUMN для снятия NOT NULL, поэтому `activity` и `effect` остаются NOT NULL на уровне схемы, но доменная логика более не требует их заполнения. Обработчик будет передавать пустую строку для обратной совместимости, когда поля не заполнены.

Альтернатива (recreate table) отклонена: миграции с потерей данных неприемлемы для production-подхода.

### 8. HTMX swap в ленту

После успешного создания записи форма сбрасывается через Hyperscript (`me.reset()`), а ответ (HTML-фрагмент записи) вставляется в `#entries-list` через `hx-swap="afterbegin"`.

Почему `afterbegin`, а не `beforeend`:
- Новые записи должны быть сверху списка (хронологически)
- Соответствует существующему порядку сортировки (date DESC)

## Risks / Trade-offs

- **Мульти-шкала → бросание.** Три range-ядра — больше одного тапа. Риск: пользователь в депрессии не хочет двигать три слайдера. Митигация: шаблон «день» = только ядро (3 движения, 5 сек); опциональные блоки скрыты; целевое время зафиксировано. `[ref: A3-q1]`
- **Range на мобилке — мелкий таргет.** Стандартный `<input type="range">` имеет низкую высоту, трудно попасть пальцем. Митигация: `style="height: 2rem"` (32px трек) + `range-lg` DaisyUI-класс; контейнер `form-control` добавляет label сверху — общая touch-зона ≥44px.
- **activity/effect NOT NULL.** SQLite не позволяет ALTER COLUMN для снятия constraints. Митигация: передаём пустую строку `""` для обратной совместимости; в будущем (при редизайне схемы) снимем через recreate.
- **Collapse сохраняет состояние при смене шаблона.** Если пользователь раскрыл «сон» в шаблоне «день» (где он не предполагается), блок остаётся раскрытым. Это не баг — пользователь всегда может заполнить что угодно. Но может создать когнитивный диссонанс. Митигация: в будущих фазах добавить динамическое скрытие по шаблону.
- **Тёмная тема — DaisyUI 5 class-based dark mode.** DaisyUI 5 поддерживает тёмную тему через `data-theme="dark"`. Не требуется tailwind dark: префиксы.
