## Context

Проект growing — 13 миграций, 10 роут-файлов, AI-домен, i18n, notifications. Но документация не поспевает: нет README, AGENTS.md неполный. Новый контрибьютор (человек или AI-агент) тратит время на разведку кода, чтобы понять базовые вещи: какие env-переменные нужны, какие фичи есть, как запускать тесты.

## Goals / Non-Goals

**Goals:**
- README.md: краткое введение в проект (что это, стек, запуск, env, тесты, фичи) — 1-2 экрана
- AGENTS.md: дополнить недостающими секциями (env vars, фичи/роуты, i18n, миграции, AI-домен)

**Non-Goals:**
- Полная архитектурная документация (живёт в `openspec/specs/`)
- Подробное описание каждого роута (живёт в коде)
- CONTRIBUTING.md, CHANGELOG.md

## Decisions

### D1: README — короткий, не энциклопедия

README = landing page для разработчика. Структура:
1. Название + 1-строчное описание
2. Стек (кратко)
3. Запуск (env vars + команда)
4. Тесты (команда)
5. Фичи (список в 1 строку на фичу)
6. Ссылка на AGENTS.md / openspec/ для деталей

### D2: AGENTS.md — обновить, не переписать

Существующий AGENTS.md хорош по структуре. Добавить секции:
- **Env vars** (новая секция после «Запуск»)
- **Обзор фич** (новая секция — краткий список доменов и роутов)
- **i18n** (краткая заметка: `app.i18n`, `t`-функция, ru/en)
- **Миграции** (краткая заметка: `resources/migrations/`, автозапуск)
- **AI-домен** (краткая заметка: OpenRouter, opt-in, graceful nil)

Не трогать существующие секции (htmx-философия, иконки, e2e — они актуальны).

### D3: Контент README и AGENTS не дублируется

README = для человека, открывшего репо впервые. AGENTS.md = для AI-агента/контрибьютора, работающего с кодом. README ссылается на AGENTS.md для конвенций и правил.

## Risks / Trade-offs

- **[Документация устареет]** → Держать секции краткими, ссылаться на код/openspec для деталей. Не дублировать то, что уже в коде.
