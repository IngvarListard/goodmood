## Context

- `AGENTS.md` — главный файл инструкций для AI-агентов. Должен содержать практические правила импорта и документирования.
- `CLOJURE-RULES.md` — архитектурные правила. Секция «Фронтенд» (п.2.4) упоминает «Hiccup v2» без конкретного import pattern.
- В коде есть публичные функции без docstring (напр., `html-response`, `create-entry`, `get-entries`, `->app`, и др.).

## Goals / Non-Goals

**Goals:**
- Добавить в AGENTS.md правило импорта hiccup (`[hiccup2.core :refer [html raw]]`)
- Добавить в AGENTS.md правило про docstrings для нетривиальных публичных функций
- Добавить в CLOJURE-RULES.md явный import pattern в секцию про Hiccup
- Добавить docstrings к нетривиальным публичным функциям

**Non-Goals:**
- Не менять поведение кода
- Не добавлять docstrings к каждой приватной функции
- Не переписывать существующие docstrings

## Decisions

| Решение | Почему |
|---|---|
| Правило в AGENTS.md, не CODESTYLE.md | AGENTS.md — инструкция для AI-агентов. CODESTYLE.md — общий стайлгайд. Агенты читают AGENTS.md в первую очередь. |
| «Нетривиальные публичные» = уровень модуля/API, не хелперы | Баланс между полезной документацией и шумом. Хелперы вроде `html-response` очевидны из названия. |
| Категоризация docstring: одна строка для простых функций, multi-line со сценариями для сложных | Соответствует CODESTYLE.md |

## Risks / Trade-offs

- [Субъективность] «Нетривиальность» может толковаться по-разному → Mitigation: явный список функций для docstring в задачах
