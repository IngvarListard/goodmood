# Proposal: add-entries-crud

## Why

Записи можно только создавать: просмотреть конкретную запись, отредактировать или удалить её негде — ни UI, ни бэкенда (в `app.db.entries` только `create-entry!`/`get-entries`, `GET /entries` редиректит на ленту). Опечатка в заметке или случайно сохранённая запись остаются навсегда, что критично для дневника, на котором строится AI-анализ.

## What Changes

- Новая страница `/entries` — список всех записей пользователя (хронологическая группировка по дням, как в ленте) с переходом к карточке записи
- Страница/карточка записи `/entries/:id` — просмотр всех полей + edit и delete
- Редактирование всех полей записи: дата, mood/energy/anxiety/focus, сон, заметка, активность, state_label (in-place edit по паттерну инсайтов)
- Удаление записи с confirm-модалкой (по паттерну удаления инсайтов)
- Бэкенд: `update-entry!`/`delete-entry!` в db- и domain-слоях, роуты `GET /entries`, `GET /entries/:id`, `POST /entries/:id`, `DELETE /entries/:id`
- Точка входа — иконка «все записи» в шапке ленты (нав не расширяется)

## Capabilities

### New Capabilities

- `entries-crud`: просмотр списка записей, карточки записи, редактирование и удаление с ограничениями владения

### Modified Capabilities

- `feed-timeline`: в шапке ленты появляется переход к полному списку записей

## Impact

- Новые: `app.db.entries` (update/delete), `app.domains.entries` (update-entry/delete-entry со схемами), `app.routes.entries` (4 роута), `app.views.entries` (страница списка/карточки/edit-формы)
- `src/app/routes/app.clj` — регистрация роутов; `resources/i18n/{ru,en}.edn` — тексты
- Удаление записи затрагивает связи: `entries.state_period_id` (период остаётся), AI-анализ использует историю записей (удалённая запись выпадает из будущих анализов); существующие AI-находки не трогаем
- Без миграций БД (колонки уже есть), без новых зависимостей

## Scope

- CRUD отдельных записей и список; собственно лента/чек-ин не меняются (кроме иконки-ссылки в шапке)

## Non-goals

- Массовое удаление/импорт-экспорт, пагинация с номерами страниц (достаточно подгрузки/прокрутки первой версии — список обычно короткий)
- Редактирование привязки к периоду состояния (state_period_id) из UI
- История правок записи (audit log)
