# Proposal: add-pwa-push

## Why

Приложение живёт в браузерной вкладке: нет иконки на рабочем столе, есть адресная строка, а уведомления (3 слота) видны только когда юзер сам открыл приложение — напоминание в момент слота теряется. Для трекера с ежедневным чек-ином это главная дыра привычки: между «пора записать» и «записал» лишние шаги, а при закрытой вкладке приложение молчит. Плюс домен уже готов: HTTPS через reverse proxy, cookie-сессия 90 дней, мобильный UI.

Владелец зафиксировал границы: **Android-first**; цель — иконка на рабочем столе, standalone без рамок/адресной строки, push-уведомления в момент слота; **офлайн-режим сознательно не делается** (htmx-приложение; если «зайдёт» — переписывание на другой стек, напр. Dart, а не доращивание офлайна). iOS — non-goal (нет install-промпта и гарантий push).

## What Changes

- Установимость (installable): `manifest.webmanifest` (standalone, иконки 192/512 + maskable, theme-color), мета-теги в layout, минимальный service worker (только для installability; сеть-онли + страница «нет сети» — кэширования данных нет)
- Push-доставка слотов: подписка через Push API (кнопка в настройках), серверный шедулер (интегрант-компонент) отправляет пуш в момент времени слота включившим юзерам; reuses `user_notification_settings` (слоты) и sentinel `last_slot_shown` — доставленный пуш не дублируется in-app баннером «пока тебя не было»
- VAPID-ключи через env (`GOODMOOD_VAPID_*`), graceful degradation без ключей (кнопка скрыта, шедулер no-op — как AI-функции)
- Новая зависимость: `nl.martijndwars/web-push` (JVM, VAPID) — последняя 5.1.2
- In-app баннеры/сводки остаются как есть для неподписанных юзеров

## Capabilities

### New Capabilities

- `pwa`: установимость + standalone + push (подписка, доставка, шедулер)

### Modified Capabilities

- `ui-shell`: head получает manifest-ссылку, theme-color meta, push.js (SW-регистрация)
- `coping-channels`: сценарий «push отложен» отменяется; доставка слота подписанному юзеру — пуш (sentinel общий с in-app)

## Impact

- Миграция `003-push-subscriptions` (endpoint UNIQUE, p256dh, auth; down с DROP TABLE)
- `app.db.push` / `app.domains.push` / `app.routes.push`: подписки, отправка, чистка мёртвых (404/410)
- `system.clj`: фоновый компонент-шедулер (тик раз в минуту; рестарт процесса нужен)
- `views/layout.clj`: manifest link + theme-color + push.js; `resources/public/{manifest.webmanifest,sw.js,js/push.js,icons/}`
- `views/settings.clj`: секция «Push-уведомления» (кнопка включить / статус)
- i18n: тексты пушей и кнопок (ru/en)
- VAPID: одноразовая генерация (dev-скрипт), ключи в `.env` / NAS `.env`
- Без миграций контента: тексты пушей — i18n, без вычисления инсайтов в payload (non-goal)

## Scope

Установимость (standalone, иконка) + push слотов на Android. Офлайн, iOS-гарантии, инсайты в пушах, список прошлых сессий-разговоров — вне scope.

## Non-goals

- Офлайн-режим (кэш ленты/записей, очередь записей) — сознательно отклонён владельцем
- Push на iOS (без install-промпта; базовая работа не гарантируется и не тестируется)
- Инсайты/персональный контекст в payload пуша (v1 — фиксированные i18n-тексты слотов)
- Vendor'инг CDN-статиков (возможен позже отдельным ченджем)
- Пакет в сторе / native-обёртки (Capacitor и т.п.) — противоречит плану переписывания
