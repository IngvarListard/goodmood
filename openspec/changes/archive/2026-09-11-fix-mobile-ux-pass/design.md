# Design: fix-mobile-ux-pass

## Context

Разведка на Nothing Phone 1 (412×915, RU) показала: нижняя панель навигации (`views/navigation.clj`) из-за «Медикаменты» (~80px при своих ~78px) роняет последний пункт на второй ряд — панель 160px вместо ~90px; паддинг контента захардкожен `5rem` (80px) в `views/layout.clj` — контент перекрыт; FAB ассистента (`views/assistant.clj`) 40×40px на `bottom-20 z-40` — под панелью (`z-50`) и физически некликабелен (подтверждено Playwright: «subtree intercepts pointer events»). Чат шлёт `hx-post /ai/chat` синхронно ждёт LLM — юзер видит ноль обратной связи. AI-карточки ленты (`views/ai.clj`) — три разные анатомии, текстовый бейдж уверенности переносится и вылезает за рамку; `confidence-badge` при nil рендерит `{Missing key …}`. E2E-чат живёт под `@ai` и требует реальный ключ OpenRouter; `call-chat` документирован «для мокинга (with-redefs)», но e2e — отдельный процесс.

## Goals / Non-Goals

- Goals: один ряд навигации на 412px/RU; FAB кликабелен и заметен; мгновенная обратная связь в чате; быстрый детерминированный e2e чата; фокус в ядре; единая анатомия AI-карточек без переносов в шапках.
- Non-Goals: CRUD записей (→ `add-entries-crud`), streaming-ответы, редизайн ленты вне AI-кластера, изменения soft-mode (Decision 14.4), миграции, новые зависимости.

## Decisions

### D1. Панель: фиксированная высота + CSS-переменная (не JS-измерение)

Высота панели фиксируется стилем (обёртка получает `--gm-nav-h: 92px`, внутри — один ряд 70px + safe-area padding). Паддинг контента: `pb-[calc(env(safe-area-inset-bottom)+var(--gm-nav-h)+0.75rem)]`, FAB: `bottom: calc(var(--gm-nav-h) + env(safe-area-inset-bottom) + 12px)`, `z-60`.
- Альтернатива (JS `offsetHeight` → inline var): решает ту же задачу, но добавляет скрипт и FOUC на первом рендере. Перенос строк исключается самим контентом (короткие подписи), поэтому константа надёжна.
- Подписи: RU «Медикаменты»→«Мед», EN «Medications»→«Meds»; порядок в `nav-items`: `[Лента, Инсайты, Запись, Мед, Настройки]`; «Отметка»→«Запись». Запас ширины: максимум «Настройки» ~63px при лимите ~78px.

### D2. Чат: оптимистичный UI средствами hyperscript, контракт htmx не меняется

На `submit` формы чата hyperscript: вставить в `#chat-response` юзер-бабл + typing-бабл («Печатает ●●●», три `animate-bounce` точки), очистить инпут, проскроллить вниз. Сервер как сейчас возвращает всю историю → свап outerHTML заменяет оптимистичный фрагмент правдой из БД. Снятие typing при ошибке: `on htmx:responseError` удаляет индикатор. Экранирование: текст вставляется через `textContent` (не innerHTML) — hyperscript `make a div … set its textContent to …` или `<template>` + textContent.
- Альтернатива (серверный OOB-фрагмент с эхом сообщения): латентность до первого байта всё равно равна времени LLM — не решает проблему. Streaming: вне скоупа.
- Edge: double-submit пока ввод «висит» — оставляем как есть (кнопка не блокируется), вреда нет: сервер вернёт консистентную историю.

### D3. Тест-дабл AI: env-флаг внутри `call-chat`, диспетч по model

В начале `call-chat`: `(if (= "1" (env/env "GOODMOOD_FAKE_AI")) (fake-reply model) …)`. `fake-reply` — 4 ветки по константам моделей, возвращают JSON, валидный по Malli-схемам (correlations — массив, advice — объект с source_refs, episode-warning — объект с confidence double, chat — текст). Покрывает весь путь parse→DB→UI; не тестируется только HTTP-слой к OpenRouter (и не должен в fast-прогоне).
- Альтернатива (env-URL на локальный мок-сервер): честнее по сети, но +сервер в e2e-инфраструктуре и ещё один порт. Отклонено как избыточное.
- В playwright.config: `GOODMOOD_FAKE_AI` ставится в `1` только когда `OPENROUTER_API_KEY` пуст — с ключом спеки `@ai` продолжают гонять реальный API.

### D4. AI-кластер: одна анатомия карточки, уверенность — дот-шкала

Единая шапка: иконка типа + короткое название типа («Возможная связь», «Совет из твоих инсайтов», «Идея не из записей», «Ярлык состояния»), дот-шкала уверенности (3 точки: high 3/primary, medium 2/warning, low 1/muted; nil → не рендерится — фикс missing-key), dismiss-крестик. Тело: `line-clamp-3` + «ещё» (гипerscript, как текущий `toast/hint-more`). Действия: иконочные ghost-кнопки с `title`/`aria-label`, тот же контракт `POST /ai/findings/:id/feedback`; `data-testid` всех секций сохраняются — текстовые локаторы e2e обновляются под новые aria-label'ы. Составные секции (`insights/feed-widget` с AI-советом под ним) сохраняют порядок блоков: ярлык → корреляции → совет → novel → график недели.

### D5. Фокус в ядре: `range-field` после тревоги

`(range-field (i18n/t :entries/focus) "focus" "focus")` в `soft-fields` перед секцией «дополнительно»; аккордеон фокуса удаляется. `data-optional`/disabled-механика для него не нужна. Мягкий режим скрывает `#soft-targets` целиком — фокус скрывается вместе с энергией/тревогой автоматически, отдельного кода не требует.

## Risks / Trade-offs

- [Оптимистичный бабл дублируется, если свап придёт медленно и юзер отправит ещё] → сервер всегда возвращает полную историю; последний свап консистентен, повторы сообщения — известный компромисс текущего контракта.
- [Хардкод `--gm-nav-h: 92px` разъедется при смене типографики навигации] → переменная объявлена в одном месте рядом со стилями панели; сценарий спеки проверяет один ряд на 412px.
- [Canned-ответы оторваны от реальных промптов] → схемы Malli общие с прод-путём; реальный API продолжают проверять `@ai`-спеки при наличии ключа.
- [Переименование фидбек-кнопок ломает существующие AI-спеки по тексту] → в tasks заложена правка локаторов на `getByTitle`/`getByRole name` одновременно с переименованием.

## Migration Plan

Без миграций БД. Деплой обычным `bin/deploy.sh`; откат — предыдущий тег. i18n-ключи переименовываются в одном коммите вместе с навигацией (`:nav/check-in` → текст «Запись» остаётся под тем же ключом — меняются только значения в `ru.edn`/`en.edn` и порядок вектора `nav-items`).
