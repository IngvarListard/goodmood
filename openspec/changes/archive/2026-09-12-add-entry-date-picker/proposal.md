# Proposal: add-entry-date-picker

## Why

Чек-ин создаёт запись только «на сегодня» — дата жёстко проставляется сервером. Если пользователь пропустил день (или хочет занести запись за вчерашний вечер), записи за ту дату не существует, и фид/радар периода видят дыру. Нужен способ выбрать дату прямо на карточке создания записи.

## What Changes

- На карточку /check-in добавляется свёрнутый опциональный блок «Дата» (там же, где выбор шаблона утро/день/вечер/событие) с нативным `<input type="date">`:
  - дефолт — серверная «сегодня» (та же политика времени, что у слот-пушей);
  - unchecked → поле disabled → не сабмитится → сервер ставит today (поведение по умолчанию не меняется);
  - выбор будущего не допускается, выбор глубже 30 дней назад не допускается (HTML-атрибуты min/max + серверная валидация).
- Дата записи бэкфиллится сквозь стек: форма → `POST /entries` → домен → БД (колонка `entries.date` уже существует, миграций нет).
- Привязка к state-периоду учитывает выбранную дату: запись цепляется к периоду, накрывающему эту дату, а не к активному на сегодня.

## Capabilities

### New Capabilities

_(нет)_

### Modified Capabilities

- `entries`: требование создания записи — теперь создаётся с датой из формы (по умолчанию сегодня, диапазон [сегодня−30; сегодня]), state_period_id выбирается по дате записи.

## Impact

- `src/app/views/check_in.clj` — новый collapse-блок с date input (реюз `optional-block`).
- `src/app/routes/entries.clj` — проброс `:date` из body в домен.
- `src/app/domains/entries.clj` — `:date` в `create-entry-schema` (regex + границы), `(or date (today))` в `create-entry`, привязка периода по дате.
- `src/app/db/state_periods.clj` — запрос «период, накрывающий дату» (если ещё нет).
- `resources/i18n/{ru,en}.edn` — 1–2 новых ключа.
- e2e: расширенный smoke-сценарий бэкфилла вчерашней записи.

## Scope

- Только создание записи (/check-in). Редактирование даты на карточке записи уже существует и не меняется.
- Будущие даты запрещены; глубина бэкфилла ограничена 30 днями (константа в домене).

## Non-goals

- Редактирование/валидация даты на карточке edit (остаётся как есть).
- Timezone-политика: дефолт и границы считаются по серверному времени, как всё в проекте.
- Изменение away-баннера, радара и слот-пушей (работают с `date` как раньше).
