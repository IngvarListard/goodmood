# Design: add-aggression-axis

## Context

Запись (`entries`) уже имеет три числовые оси 0–10: `energy`, `anxiety`,
`focus` (все nullable, добавлены в `001-init` без CHECK). Домен
`app.domains.entries` валидирует диапазон malli-схемами; `app.db.entries`
строит honeysql-карты. Форма чек-ина рендерит ядро как range-слайдеры
(`range-field`), лента — чипы метрик (`metric-chip`) в `grid-cols-3`.
Радар розы ветров (3–4 оси) трогать нельзя — его переделывает
`replace-radar-with-time-chart`.

Нужна четвёртая ось «агрессия» с **обратной полярностью** (высокое — плохо).
Владельцем принято: ввод — range-слайдер 0–10 с краевыми якорями
«Добрячок»/«Мудак», хранение целым числом, чтобы числа шли в будущие графики.

## Decisions

### D1. Миграция 004 — nullable INTEGER без CHECK

`004-aggression-axis.up.sql`: `ALTER TABLE entries ADD COLUMN aggression
INTEGER;` — тем же приёмом, что energy/anxiety/focus в `001-init` (ALTER с
CHECK в SQLite не поддерживается). Nullable сохраняет совместимость со старыми
записями; 0–10 валидирует домен. `down.sql` дропает колонку.

Tradeoff: диапазон не гарантирован на уровне БД, только домен. Для этого
проекта приемлемо — energy/anxiety устроены так же.

### D2. Hybrid-ввод: слайдер + краевые якоря, значение целое

Range-слайдер 0–10 даёт консистентность с остальными осями (жест, touch,
live-значение) и целое число для графиков. Краевые подписи несут семантику
направления, которой у чисел нет: слева «Добрячок», справа «Мудак».

Tradeoff: якорные подписи неформальные и могут резать глаз; это осознанное
решение владельца. Слайдер сохраняет нейтральный числовой контракт (0–10),
подписи — только UI-обвязка, локализуются через i18n.

### D3. Обратная полярность — только в семантике, не в ядре правил

Высокая агрессия = плохо. Ничего в текущем коде это не «переворачивает»:
`state-label` агрессию не использует (см. D4), радар не меняется. Инверсия
понадобится будущему композиту «общее настроение» в
`replace-radar-with-time-chart` — там её и реализуют, с явным учётом полярности.

Tradeoff: инверсия «размазана» по будущим потребителям, а не зашита в
хранение. Зато хранимое значение — честная шкала 0–10 (0 = спокойствие,
10 = максимум агрессии), без скрытых преобразований.

### D4. Rule-based `state-label` не трогаем

`state-label` — детерминированная функция от energy/anxiety. Агрессия в неё не
входит: это отдельная ось, а не компонент ярлыка. Явный non-goal, чтобы не
ломать существующие тесты и поведение.

### D5. Схемы домена: опциональное поле

`:aggression {:optional true} [:maybe [:int {:min 0 :max 10}]]` в
`create-entry-schema` и `update-entry-schema`; `:aggression` в
`updatable-fields`. В `create-entry` пробрасывается как есть. Поле опционально
(как focus): старые клиенты и API без агрессии работают, запись сохраняется с
NULL.

### D6. Лента: 2×2 вместо 4 в ряд

Чип агрессии — четвёртый. `grid-cols-4` на 375px сжимает чипы до
нечитаемости, поэтому `grid-cols-2` (2×2). Tradeoff: карточка чуть выше; на
мобильном читаемость важнее плотности.

### D7. Цвет и иконка агрессии

CSS-переменная `--gm-metric-aggression` в `:root` (`layout.clj`) рядом с
energy/anxiety/focus. Цвет — красновато-фиолетовый `#c0407f` (отличается и от
красного anxiety `#e05545`, и от синего focus). Иконка чипа — `hand-raised`
(heroicons), через существующий `metric-chip`.

### D8. i18n — оба файла в синхроне

Ключи: `:entries/aggression` (label слайдера/чипа), `:entries/aggression-left`
(«Добрячок» / en «Sweetheart»), `:entries/aggression-right` («Мудак» / en
«Jerk»). Правки — и в `ru.edn`, и в `en.edn`.

## Risks

- **SQLite DROP COLUMN**: поддерживается с SQLite 3.35 (2021). Если рантайм
  старше — `down.sql` использует fallback через пересоздание таблицы
  (create new → copy → drop → rename). В комментарии миграции зафиксировать.
- **Якорные подписи** («Мудак») могут быть восприняты как оскорбительные/не
  инклюзивные — осознанное решение владельца, локализовано, легко меняется.
- **Обратная полярность** — источник будущих ошибок агрегации; зафиксирована в
  proposal/design и должна быть учтена в `replace-radar-with-time-chart`.
- **Плотность ленты** после перехода на 2×2 — визуальная регрессия; проверяется
  e2e/Playwright.

## Verification

- Миграция вверх и вниз на пустой БД: `rm resources/goodmood.db* && ./bin/dev`,
  затем `PRAGMA table_info(entries)` содержит `aggression`; откат —
  `down.sql` колонку убирает.
- Создание записи с `aggression` = 7 сохраняется (домен → БД → `get-entries`).
- Значение 15 отклоняется malli-валидацией, строка не вставляется.
- Слайдер агрессии рендерится с краевыми подписями «Добрячок»/«Мудак» на
  /check-in.
- Лента показывает чип агрессии (2×2), edit/read на /entries/:id — слайдер и
  строку осей.
- Тесты: `test/app/routes/app_test.clj`, `test/app/db/entries_test.clj`; e2e
  `npm run test:fast`.
