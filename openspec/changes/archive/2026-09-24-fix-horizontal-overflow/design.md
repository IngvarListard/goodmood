# Design: fix-horizontal-overflow

## Context

Симптом: у активного периода с длинным названием страница ленты уезжает по
горизонтали. Корневая причина подтверждена в коде: в
`app.views.state-periods/active-indicator` градиентный pill — прямой
flex-потомок ряда `flex items-center justify-between gap-3`; pill имеет
`whitespace-nowrap`, но ни `min-w-0`, ни `truncate`, а сосед — кнопка «Закрыть
период». Flex-элемент по умолчанию имеет `min-width: auto` и не сжимается ниже
своего содержимого, поэтому длинная подпись толкает ряд шире контентной
колонки `max-w-lg` (`layout`) и создаёт страничный горизонтальный скролл.
`period-list` рендерит название в `<p>` — длинный токен без пробелов там тоже
не переносится и расширяет колонку.

По конвенциям (CLOJURE-RULES): вьюхи — чистые функции, hiccup; ограничение
отображения — визуальный слой, данные не трогаем. Стек фронтенда
(AGENTS) — Tailwind + DaisyUI без собственного CSS.

## Decisions

### D1. Пилюля периода: `min-w-0` на flex-потомке + `truncate` на подписи

В `active-indicator` pill получает `min-w-0 flex-1`, подпись `(:label
period)` — `truncate` (`overflow-hidden text-ellipsis whitespace-nowrap`,
что поглощает уже имеющийся `whitespace-nowrap`), кнопка — `shrink-0`.
Это ровно тот минимум, что снимает `min-width: auto`-блок: подпись
ellipsizes, кнопка остаётся видимой.
- Rationale: правило flex `min-width:auto` — причина переполнения, фикс в
  одном месте.
- Tradeoff: длинное название видно не полностью (многоточие) — осознанно,
  это UI-обрезка, данные не теряются.

### D2. `period-list`: перенос длинных названий (`break-words`)

В `period-list` название периода остаётся в `<p>` без обрезки в одну строку
(там важен полный текст ретроспективы), поэтому добавляем `break-words`
(`overflow-wrap`), чтобы длинный токен ломался внутри колонки.
- Rationale: для read-only ретроспективы перенос лучше ellipsis.
- Tradeoff: длинное имя займёт несколько строк — приемлемо.

### D3. Общая норма — требование в `ui-shell`, реализация по месту

Добавляем одно требование в `ui-shell`: текст не расширяет колонку; для
flex-ряда с текстом — `min-w-0` на текстовом потомке плюс `truncate`
(однострочное) или `break-words`/`line-clamp-N` (многострочное). Доменные
спеки `feed-timeline` и `entries-crud` дают сценарии-якоря для проверки.
- Rationale: одна норма на всю оболочку, чтобы фикс не остался точечным
  только про пилюлю; доменные сценарии — проверяемые критерии приёмки.
- Tradeoff: формулировка частично дублируется между общей и доменными
  спеками — цена явности.

### D4. Классы — только существующие Tailwind/DaisyUI-утилиты

Используем `min-w-0`, `truncate`, `break-words`, `line-clamp-N`. Собственных
CSS-классов не добавляем.
- Rationale: AGENTS/CLOJURE-RULES — компоненты из Tailwind/DaisyUI, кастом
  минимален.
- Tradeoff: там, где нужен именно перенос, предпочитаем `break-words`, а не
  `line-clamp`, чтобы не зависеть от поведения browser-CDN для clamp.

### D5. Данные не ограничиваем

Ни `max-length` в Malli-схемах, ни миграций, ни обрезки в домене.
- Rationale: это гигиена отображения, а не валидация данных; симметрично
  Non-goals proposal.
- Tradeoff: экстремально длинный текст остаётся в БД — компактный вид
  обеспечивает вьюха.

## Risks

- [Стандартная утилита не применилась/не собралась в Tailwind CDN] →
  используем только стандартные классы; в Playwright проверяем фактический
  `scrollWidth`, а не наличие класса в HTML.
- [Обрезка спрячет значимый текст] → `truncate` только для однострочных
  подписей (период, оси, ярлык состояния); заметки и активность —
  `break-words`.
- [Правка разметки ломает htmx-контракты] → меняются только классы/обёртки
  внутри тех же элементов, `hx-*`/csrf не трогаются; закрытие периода и
  редактирование записи перепроверяются в Playwright.

## Verification

- Playwright на viewport 360px: активный период с названием ~60 символов
  одним токеном → `document.documentElement.scrollWidth <=
  document.documentElement.clientWidth`.
- То же для длинной заметки записи и длинной строки AI-инсайта/чата.
- Обе локали (`ru`, `en`) и обе темы (light/dark) — 4 комбинации без
  горизонтального скролла.
- Проверки выполняются на реальных страницах через UI (не только
  standalone-фрагмент).
