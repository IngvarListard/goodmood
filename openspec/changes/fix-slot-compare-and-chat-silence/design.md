## Context

Два независимых бага в production-коде:

1. **`past-slot-time?`** (`notifications.clj:37-44`) — функция сравнивает время слота с текущим через `>=` на строках `"HH:MM"`. `>=` вызывает `Numbers.gte`, который требует числовые аргументы → `ClassCastException`. Это ломает polling-баннер `/feed/pending-insight` для всех пользователей с включёнными слотами уведомлений.

2. **AI-чат молчит** — `call-chat` (`domains/ai.clj:83-106`) возвращает `nil` при: отсутствии `OPENROUTER_API_KEY`, ошибке сети, non-200. В `chat-send` (`routes/ai.clj:162-168`) `reply = nil` → ассистент-сообщение не сохраняется → пользователь видит только своё сообщение. Случай «нет ключа» не логируется вообще.

## Goals / Non-Goals

**Goals:**
- `past-slot-time?` корректно сравнивает время и не падает
- При недоступности AI-чата пользователь видит понятное фолбэк-сообщение
- Отсутствие `OPENROUTER_API_KEY` логируется (для диагностики)

**Non-Goals:**
- Не добавляем retry/backoff для AI-вызовов
- Не добавляем UI-индикацию статуса API-ключа
- Не меняем логику crisis-детекции
- Не трогаем другие AI-функции (correlations, labels, advice) — там nil-фолбэк уже работает (просто возвращает пустой фрагмент)

## Decisions

### D1: `past-slot-time?` — сравнение в минутах с полуночи

Сравнивать числовое представление: `h*60 + m` для слота и для текущего времени.

**Альтернативы:**
- `compare` на строках `"HH:MM"` — работает лексикографически для фиксированной ширины, но менее очевидно и хрупко (если формат времени изменится).
- `<=`/`>=` на отдельных `h` и `m` — многословнее, та же суть.

**Выбор:** минуты с полуночи — самый явный и числовой подход.

### D2: Фолбэк-сообщение в чате при `reply = nil`

В `chat-send`: когда `reply` — nil (после `chat-reply`), сохранять user-сообщение, но вместо ассистент-ответа рендерить фолбэк-пузырь с текстом вроде «Не удалось получить ответ, попробуйте позже».

Фолбэк НЕ сохраняется в `ai_chat_messages` (это не реальный ответ ассистента, и не должен попадать в контекст истории следующих запросов).

### D3: Логирование отсутствия API-ключа

В `call-chat`: когда `(seq key)` — false, добавить `println` с понятным сообщением (`"OpenRouter API key not set — skipping AI call"`). Это не error-level (AI опционален), но должно быть видно в логах.

## Risks / Trade-offs

- **[Фолбэк-сообщение не локализовано]** → Использовать `i18n/t` с ключом `:ai/chat-error-fallback`, добавить переводы ru/en.
- **[Фолбэк-сообщение может скрыть реальную проблему]** → Логировать причину nil (нет ключа / non-200 / сеть) на сервере, фолбэк — только для пользователя.
