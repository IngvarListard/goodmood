## Context

Новый проект трекера настроения для людей с биполярным расстройством. Сейчас нет ни кода, ни инфраструктуры. Нужно поднять минимальный скелет приложения, чтобы иметь точку входа для дальнейшей разработки.

**Текущее состояние**: пустой репозиторий.

**Стек**: Clojure, deps.edn, ring + ring-jetty-adapter, reitit, integrant, hiccup2, htmx, hyperscript, Tailwind + DaisyUI, SQLite, next.jdbc, HoneySQL, migratus.

## Goals / Non-Goals

**Goals:**
- Рабочий HTTP-сервер, отвечающий на запросы
- Управляемый жизненный цикл компонентов (старт/остановка)
- Точка входа для запуска через `clj -M -m app.core`

**Non-Goals:**
- База данных, шаблоны, htmx, бизнес-логика
- Аутентификация, авторизация
- Тестирование, CI/CD
- Деплой, продакшн-конфигурация

## Decisions

### 1. Компонентная модель: Integrant

**Решение**: Использовать integrant для управления жизненным циклом компонентов.

**Почему integrant**:
- Легковесный, минимальный learning curve
- Явная инициализация и деинициализация компонентов
- Хорошо интегрируется с Ring (есть готовые паттерны)
- Соответствует стеку проекта

**Альтернативы**:
- Component — более тяжёлый, больше boilerplate
- Mount — менее явный жизненный цикл, сложнее тестировать
- Собственное решение — нет преимуществ перед проверенными библиотеками

### 2. Роутинг: Reitit

**Решение**: Использовать reitit для маршрутизации.

**Почему reitit**:
- Декларативный подход к определению роутов
- Поддержка middleware из коробки
- Хорошая интеграция с Ring
- Активно поддерживается, хорошая документация

**Альтернативы**:
- Compojure — более старый, менее гибкий синтаксис
- Bidi — менее популярный, меньше сообщество

### 3. HTTP-сервер: Ring Jetty

**Решение**: Использовать ring-jetty-adapter.

**Почему Jetty**:
- Стандартный выбор для Ring-приложений
- Хорошая производительность для большинства задач
- Простая конфигурация

### 4. Структура проекта

```
src/
  app/
    core.clj       ; main -точка входа, запуск integrant-системы
    system.clj     ; конфигурация integrant-системы
    routes.clj     ; reitit-роутер с health-check
```

**Почему такая структура**:
- Минимальная, но масштабируемая
- Чёткое разделение ответственности
- Соответствует конвенциям Clojure-проектов

## Risks / Trade-offs

| Risk | Mitigation |
|------|------------|
| Integrant может быть избыточен для одного компонента | Для текущей задачи — acceptable. При добавлении БД и других компонентов окупится |
| Jetty может не справиться с высокой нагрузкой | Для трекера настроения — не критично. При необходимости можно заменить на http-kit |
| Нет health-check для мониторинга | Реализован GET / → 200 OK. При необходимости можно расширить |
