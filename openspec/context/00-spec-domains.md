# Карта спец-доменов

Главные спеки в `openspec/specs/` организуются **по областям поведения** (feature / bounded context), а не по слоям реализации. Одна фича может менять несколько доменов; один домен накапливает многие фичи. При архивации дельта-спека изменения вливается в существующий домен — новый домен создаётся только когда появляется действительно новая область поведения.

## Целевой набор доменов (7)

| Домен            | Что в него входит                                        |
|------------------|----------------------------------------------------------|
| `entries`        | Запись дневника: форма, check-in, feed, mood/rose, все поля записи |
| `medications`    | Приём препаратов                                         |
| `insights`       | Аналитика / графики                                      |
| `users-auth`     | Аккаунт, вход, сессии                                    |
| `i18n`           | Локализация (ru/en)                                      |
| `ui-shell`       | Навигация, layout, заглушки, оформление                  |
| `platform`       | Инфраструктура: http-server, db-connection, db-migrations |

## Маппинг текущих доменов → целевые

```
entries       ← entries-api + entries-data + entries-ui
                 + entry-granularity + mobile-entry + mood-states
medications   ← medications
insights      ← insights
users-auth    ← users (из add-users-auth-i18n)
i18n          ← i18n (из add-users-auth-i18n)
ui-shell      ← layout + navigation + placeholder-pages
platform      ← http-server + db-connection + db-migrations
```

## Принципы

- Домен = область поведения (feature area / bounded context), а НЕ слой (api/data/ui) и НЕ разовый пропозал.
- Пропозал по умолчанию модифицирует существующие домены, а не заводит новый.
- Ретрай домена при опустении его требований — через `retire_capabilities: true` в change.
- Гранулярность пропорциональна размеру системы: трекеру настроения хватает ~6-9 устойчивых доменов.
